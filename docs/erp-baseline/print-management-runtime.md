# Print-management runtime prerequisites

Branding assets are uploaded to authenticated Laravel endpoints and stored on the private `local` disk under a company-specific path. The application currently accepts raster PNG, JPEG and WebP, and converts static GIF/BMP to PNG when PHP GD is available. SVG and TIFF are not accepted. Application validation limits decoded images to 2 MiB, 6000 pixels per edge and 16 million pixels in total.

Before deploying, configure the actual PHP web-server/FPM process with a writable `upload_tmp_dir` and `sys_temp_dir`. Confirm the process identity can create and remove a temporary file there; a missing temporary directory can cause a small multipart upload to fail **before Laravel receives the request**. Keep `file_uploads=On`, set `upload_max_filesize` at least 2M and `post_max_size` comfortably above it (for example 8M to allow multipart overhead). Confirm `extension=gd` if GIF/BMP conversion is required. Restart PHP-FPM/web workers after PHP configuration changes. Do not use a web-public directory for temporary files.

Local reproduction on 2026-09-21: a 94,044-byte PNG failed with `PHP Request Startup: File upload error - unable to create a temporary file`; the same multipart request reached Laravel after the local PHP server was started with explicit writable upload/system temporary directories. This is an environment prerequisite, not evidence that production PHP has the same fault. Verify it on staging without exposing credentials or changing production configuration blindly.

Migration `2026_09_21_000027_create_central_print_documents.php` adds private watermark metadata, official-document print metadata, and the road-waybill table. It must be reviewed and applied through the normal release process on the target database; do not run it against production as part of local UAT. Browser print-to-PDF and the server-side report PDF are independent rendering paths and require separate visual checks.

Server-generated report PDFs use an installed Chromium-family browser for correct Arabic shaping and bidirectional text. Set `SULB_PDF_CHROMIUM_PATH` to an explicitly managed Chrome, Chromium, or Edge executable in staging/production. The application invokes it with an argument array (not a shell command), a unique private profile, local HTML with embedded private branding images, disabled background networking, and a 60-second timeout; temporary HTML/PDF/profile files are removed after every attempt. Dompdf remains installed for compatibility but is not used by the advanced-report PDF export because it does not provide complete Arabic shaping/BiDi. Keep the browser patched and ensure the PHP worker can execute it and write `storage/framework/pdf-render`.
