# مراجعة خاصة لربط كتّاب الإنتاج — دون تغيير الإنتاج

## لماذا لم يكتمل التحقق السابق؟

1. الأداة السابقة كانت تثبت الصلاحيات وبصمات الملفات؛ لا تثبت الإعدادات الفعالة للعمليات. تصريحات .env قد تختلف عن config cache أو تعديلات Providers أو إعدادات Workers قديمة.
2. اسم مستخدم MySQL وحده لا يثبت هوية user@host التي صودق عليها. تطابق اسم الجلسة قد يطابق أكثر من حساب؛ لا يُحسم هذا تلقائيًا.
3. وجود مرجع للموقع أو UID أو ملف خدمة لا يثبت أن العملية تستخدم حسابًا بعينه. العمليات العابرة أو المتوقفة والعملاء الخارجيون لا يغطيها جرد لحظي.
4. بصمات 324 ملفًا لا تثبت مراجعة دلالة الأوامر والبرامج المتفرعة أو ربطها بحسابات قاعدة البيانات.
5. تطابق 115 ملف مصدر يثبت سلامة هذه الملفات فقط؛ ليس حصرًا لكل كاتب حي أو خارجي.
6. allowlist فارغة، ولم يصدر اعتماد المسؤول للكتّاب والمهام أو مبررات الصلاحيات. تبقى الحسابات الخمسة غير معتمدة.

## ما يجمعه الفحص الإضافي؟

نفس الأمر الموجود `php ops/sulb-rc/release-fence.php --review-profile`، بعد تحديث فرع RC، ينفذ قراءة metadata فقط داخل معاملة READ ONLY. لا يستخدم Artisan ولا يحمّل كود الموقع ولا يتصل بحساب التطبيق. مسار CloudPanel الإداري الموجود يوفر الاعتماد في الذاكرة فقط لقراءة metadata؛ لا يُنشأ حساب أو تُعدّل صلاحيات.

- أسباب اعتبار الحساب كاتبًا: صلاحيات عامة أو إدارية أو ديناميكية، أو صلاحيات sulbprod على مستوى schema/table/column/routine أو proxy. لا تُقرأ أعمدة كلمات المرور أو مصادقة المستخدمين.
- يقرأ config cache كصيغة literal محدودة دون include/eval أو تشغيل أي كود. أي تعبير أو استدعاء أو مرجع ديناميكي أو صيغة غير مدعومة يترك الإعدادات غير مثبتة، ولا تُستخدم .env بديلًا لتجاوز cache غير مفهوم.
- يستخرج مرشحي الحساب من اسم المستخدم وقاعدة sulbprod فقط، دون نسخ كلمات المرور أو DSN أو المضيف. يحتفظ بأسماء الحسابات في الملف الخاص، ولا يطبعها في الملخص.
- يربط القرائن بملفات الخدمات والمهام وبهوية PID/start_ticks/UID واسم وحدة cgroup عند توفرها. لا يُعتبر ذلك إثبات مصادقة، ولا تُنفذ البرامج المشار إليها.
- ينشئ قائمة مراجعة لكل حساب، بما فيه الحساب المقفل، ولكل خدمة/مهمة مرشحة. حقول المالك والقرار والمبرر والمرجع والتاريخ فارغة. لكل صلاحية مرصودة خانة مستقلة لسبب الاحتياج والقرار.

## ما يعتمده المسؤول محليًا؟

يبقى الملف خارج htdocs بصلاحيات root:0700/0600. لا يُرفع إلى GitHub أو المحادثة. تُراجع أسماء الحسابات والصلاحيات والروابط داخليًا بواسطة مسؤول التشغيل وقاعدة البيانات.

لكل حساب: يحدد المخوّل المالك والخدمة أو دور الإدارة، ومبرر كل صلاحية، وهل يستخدم sulbprod فعلًا، وكيف سيُستبعد من الكتابة أثناء الصيانة. الحساب العام/الإداري يحتاج مبررًا مستقلًا ولا يُعامل كحساب تطبيق. الحساب المقفل لا يُفتح ولا يُلغى قفله ضمن هذه المراجعة. يرفق مرجع القرار وتاريخه وبصمة دليل الربط الخاص.

لكل Worker أو Cron أو Scheduler: يراجع المخوّل ملف الخدمة والبرامج المتفرعة والإعدادات المعلنة والهوية المستخدمة، ويسجل مرجع المراجعة وبصمة الأدلة في الحقول الخاصة. المطابقة القائمة على الاسم أو UID وحدها غير كافية. تُوثق أيضًا العمليات المتوقفة والعملاء الخارجيون أو يُصرّح بأنها غير محصورة؛ لا يُدعى PASS بسبب عدم ظهور جلسة.

هذا الفحص لا يغيّر review.complete أو external_writers_and_schedules_reviewed أو allowlist أو Manifest إلى موافق. لا تُنقل القائمة المقترحة تلقائيًا إلى القائمة المعتمدة. بعد المراجعة الفعلية فقط تُراجع تغييرات ملف الاعتماد وبصمته بصورة مستقلة؛ لا يكفي تغيير حالة من false إلى true لخلق دليل ناقص. أي صلاحية غير مبررة أو كاتب غير محسوم يبقي النشر NO-GO.

## المشاركة الآمنة

أرسل ملخص Terminal فقط: linkage_status، config_binding_status، account_review_rows، service_schedule_candidates، missing_proof_categories، source_writer_hash_mismatches، profile_sha256 والحالة العامة. هذه عدادات وحالات دون أسماء الحسابات أو قيم الإعدادات. لا ترسل profile-private.json أو config.php أو .env أو نصوص Cron أو بيانات الاعتماد. لا يحتوي الأمر على Backfill أو Migration أو Deploy أو إيقاف خدمة.

لتقليل حجم الملف الخاص، تُحفظ بصمة كل ملف سطح تشغيل كاملة، وتُفصّل الأسطر ذات قرائن الكتابة أو الموقع فقط. يُسجّل عدد الأسطر الأخرى في unclassified_entry_count، وتبقى full_file_content_reviewed=false. حذف النص الخام من التقرير ليس اعتمادًا لتلك الأسطر؛ يلزم فحص محتوى الملفات والبرامج المتفرعة داخليًا. بصمات المصدر الـ115 تخص ملفات المرشح ولا تثبت مطابقة كل كود الإنتاج أو غياب كود خارج الجرد.
